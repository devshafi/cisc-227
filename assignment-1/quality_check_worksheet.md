# Requirements Quality-Check Worksheet

Use this worksheet on **both** your group's consolidated requirements list and
the AI-generated requirements list (fill out one copy of the table for each).

For every requirement, mark each of the six attributes Pass / Fail, and add a
short note explaining a Fail (or anything borderline). A single requirement can
fail more than one attribute.

## Attribute definitions

| Attribute | Question to ask |
|---|---|
| **Conflict** | Does this requirement contradict another requirement (e.g. from a different stakeholder)? |
| **Ambiguity** | Could two reasonable people read this requirement and implement it differently? |
| **Completeness** | Is anything missing that's needed to actually act on this requirement (e.g. thresholds, who, when)? |
| **Consistency** | Does this requirement use terms/definitions the same way as the rest of the list? |
| **Testability** | Could you write a concrete pass/fail test for this requirement as written? |
| **Evolvability** | Is this requirement written in a way that would break or need a full rewrite if a small related feature were added later? |

## For every requirement that fails an attribute

Write 1-2 sentences on how you resolved it (e.g. rewrote it, split it into two
requirements, flagged it as an open conflict for the client to decide, discarded
it). For conflicts specifically, do not just pick a side — document the conflict,
who holds each position, and either a compromise or an explicit note that it's
an open decision for the client (Director / Operations Manager).
